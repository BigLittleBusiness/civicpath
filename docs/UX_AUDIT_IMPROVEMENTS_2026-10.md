# CivicPath UX and Self-Service Improvements — October 2026

## Purpose

This release resolves the product-side improvements identified in the October 2026 UX audit without changing CivicPath’s standalone product boundary, tenancy model or the developer’s unrelated work. Changes are additive and tenant-scoped.

## 1. Trust, registration and public journeys

- Published in-app **Service Terms** and **Privacy Notice** routes at `/terms` and `/privacy`.
- Registration consent links directly to those pages; terms and privacy acknowledgement remain required before checkout.
- Added a protected public contact route at `/contact` with ALTCHA verification, honeypot protection, privacy acknowledgement, category-specific routing and a clear completion state.
- Every public enquiry now receives a branded confirmation attempt, not only Council Proof enquiries. Internal alert and confirmation state remain visible to System Administrators.
- Registration remains deliberately gated by verified Stripe payment; this is a commercial and security boundary, not an onboarding omission.

## 2. Guided Council setup and data import

- Added a Dashboard **Guided setup** checklist for workspace ownership, project-register import, strategy workspace creation and People & Access continuity.
- Added functional Workspace Profile controls for Organisation Administrators: Council name, operating contact, accountable workspace owner and onboarding completion audit trail.
- Replaced the settings import placeholder with project/grant CSV template download, API-backed preview, explicit confirmation and tenant-scoped commit.
- The existing strategy workspace retains its controlled action-import flow. No import copies demonstration data into a Council tenant.

## 3. Access and interaction quality

- Added a visible keyboard skip link to the shared application shell and a reliable main-content target.
- Removed misleading header search/notification controls and the non-functional workspace-switcher control; the remaining controls have a current action.
- Expanded responsive styles for the setup checklist, import review, operations monitor, public contact and policy pages.
- Existing semantic labels, focus styles, form validation, error messages and reduced-motion handling remain in place.

## 4. Support, privacy and policy operations

- New support cases receive a category-aware first-response target (4 business hours urgent, 8 business hours high, 1 business day normal, 3 business days low).
- System Admin records the first response automatically when a case enters progress, allows priority management, and displays pending/responded/overdue status.
- Support attachments remain private and are never exposed through public URLs.
- The product privacy notice states the intended Binary Lane, AWS SES, AWS S3, Stripe and Zoho service boundaries without claiming that unconfigured services are live.

## 5. Platform operations and message delivery

- Added `NotificationDelivery` outcome records for registration checkout, account activation, password reset, Council invitations and refund request emails.
- System Admin has a **Message delivery** monitor that displays provider outcome and safe retry guidance only. It never stores an email body, password-reset token or invitation link.
- Public enquiry operations display separate internal-alert and recipient-confirmation delivery state.
- Failed password-reset or invitation messages are regenerated by the original secured flow after configuration/recipient correction; historical sensitive links are not replayed.

## Production commissioning still required

These are operational prerequisites, not product gaps:

1. Configure and verify AWS SES sender identity, credentials, reply-to route and production DNS.
2. Configure Stripe test mode and complete real checkout/webhook/customer-portal/refund verification before any live activation.
3. Configure Binary Lane HTTPS, production secret storage, database backup/restore process and the final data-retention schedule.
4. Train System Administrators on support targets, People & Access continuity and safe handling of private attachments.

## Validation

- API migration `013_self_service_operations` is additive-only: it adds profile/support-target fields and the message-outcome table without altering or dropping existing Council or developer data.
- API unit regression suite and the front-end production build should be run before promotion. The People & Access end-to-end flow covers workspace-profile self-service alongside invitation, seat-limit and ownership-handover controls.
